# Tagvico AI v3.4.0

Tagvico 3.4.0 repositions the product around the Action Center, makes both
family bots proactive and hardened, and pins the Paperless-ngx API version.

## Highlights

- **Sharper product focus.** Paperless-ngx v3 ships native AI metadata
  suggestions, so Tagvico now leads with what Paperless does not build:
  Action Cases, households, the approval boundary, and the family bots.
  Reviewable AI metadata filing remains an opt-in included utility, with
  documented coexistence guidance — never two automatic writers on the same
  fields.
- **Maintenance mode for v4 removal candidates.** OCR rescue, the
  ChatGPT-subscription (Codex) adapter, the GitHub Copilot adapter, and
  OpenAI Flex/Batch modes stay fully supported through v3 with bug and
  security fixes, but gain no new capabilities. See `docs/v4-plan.md`.
- **Proactive action reminders on both bots.** Linked household members get
  DM reminders for actions that are overdue or due within three days;
  assigned cases go to the assignee, unassigned cases to every linked
  member, at most one message per case, user, and day. Disable with
  `TELEGRAM_ACTION_REMINDERS=no` / `DISCORD_ACTION_REMINDERS=no`.
- **Bot hardening.** Per-user flood limits on questions, uploads, and
  downloads; untrusted document titles escaped before entering the model
  prompt; Telegram bot token scrubbed from transport error logs; Discord
  document buttons capped at the API maximum of 25; discord.js deprecation
  warnings removed.
- **Paperless-ngx API version pinned to 9.** Paperless-ngx 3.x defaults to
  API version 10 (paginated tasks, renamed task fields); pinning keeps
  Tagvico's behavior identical on 2.16 through 3.x. Supported minimum:
  Paperless-ngx 2.16.0, reported plainly by setup when an older instance
  answers.

## Upgrade

Back up the `tagvico_ai_data` volume, pin
`ghcr.io/arturict/tagvico-ai:3.4.0`, and recreate only the Tagvico container.
This release does not change the data schema. If linked bot users should not
receive proactive reminders, set `TELEGRAM_ACTION_REMINDERS=no` and/or
`DISCORD_ACTION_REMINDERS=no` before recreating the container.
